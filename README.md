# AI2B · 个人币圈分析师

一个面向币安 USDT 永续合约的中文行情工作台，围绕四件事：**分析、投入建议、自选币持续盯盘、Telegram 报告推送**。

当前版本提供币安 USDT 永续行情、多空条件计划与保证金测算。技术规则分析可独立运行；AI 综合分析须配置模型，结合本次合约快照与已取得的新闻摘要进行解读。所有操作均为行情读取、报告生成和通知，不包含交易所下单接口。

从旧版升级：旧现货持仓与报告保留，现货持仓排除合约测算，旧现货价格预警停用。请重新核对权益、杠杆、合约持仓，并按合约价位创建预警。

## 启动

安装 Git 和 Python 3.10 或更高版本后，克隆仓库并启动。运行时无需安装第三方依赖。

```bash
git clone https://github.com/kch-space/ai2b.git
cd ai2b
python3.12 app.py
```

本机打开 `http://127.0.0.1:8765`，其他设备使用 `http://服务器IP:8765`。默认监听 `0.0.0.0`（所有网卡），需允许对应端口通过服务器防火墙。如果 `python3` 已经是 3.10+，也可使用 `python3 app.py`。如端口占用，增加 `--port 8766`。

体验合成数据：

```bash
python3.12 app.py --demo
```

页面和报告会明确标注演示模式。也可在「偏好与连接」切换。真实行情连接失败时显示错误，**不会自动伪装成演示行情**。

## Docker 部署

安装 Git、Docker Engine / Docker Desktop 和 Docker Compose 后，克隆仓库并启动。已克隆仓库的用户可直接在项目目录执行 Docker Compose 命令。

```bash
git clone https://github.com/kch-space/ai2b.git
cd ai2b
docker compose up -d --build
docker compose ps
docker compose logs -f --tail=100 ai2b
```

打开 `http://127.0.0.1:8765`。首次构建需要联网下载基础镜像与系统包，运行时无需安装 Python。可直接在网页配置模型和 Telegram，也可先复制 `.env.example` 为 `.env` 填写连接参数。

原 Python 服务占用 8765 时，可以使用 `AI2B_PORT=8766 docker compose up -d --build`，然后访问 `http://127.0.0.1:8766`。也可在 `.env` 设置 `AI2B_PORT=8766`。

Compose 默认将端口发布到 `0.0.0.0`，可通过 `http://服务器IP:8765` 或配置好的反向代理域名访问。使用非 root 用户运行，包含健康检查、日志轮转和容器重启策略。设置、密钥、持仓和报告保存在 `ai2b_data` 命名卷中，重建容器后保留；它与本地 Python 的 `.data/` 是两份独立数据。`.env`、`.data/` 和 Git 历史均不进入镜像。

停止：`docker compose down`。更新代码后执行 `docker compose up -d --build`。**不要使用 `docker compose down -v`，除非确实要删除全部容器数据。**

服务器访问、备份、迁移和演示模式见 [Docker 部署说明](docs/docker.md)。

## 当前功能

- 高对比看板：正文与图表标注增大，区分最新成交价、标记价、指数价和行情时间。
- 合约市场：只接币安正在交易的 USDT 永续合约，不混用现货、交割合约、币本位或其他交易所。
- 行情分析：已收盘成交价 K 线、多周期 EMA20/EMA50、RSI、ATR、成交量、支撑阻力及多空触发条件。
- 衍生品：当前资金费率、下一次结算时间、标记价和合约未平仓量；持仓量注明基础币单位与时间，不等于资金流入。
- 仓位计划：计划杠杆 1–20 倍，分开展示名义仓位、估算初始保证金、风险预算与止损损失。
- 持仓：手动记录合约多空方向、基础币数量、开仓价及杠杆。每币种一个净持仓；浮盈亏按标记价估算。
- 自选与预警：最多 20 个 USDT 永续交易对，每 15 秒轮询；最新成交价到价触发一次。网页每 3 秒读取缓存。
- 分析模式：规则模式绝不调用模型；AI 模式必须配置模型，调用失败明确报错，不用规则报告冒充 AI。
- 新闻：读取 CoinDesk / Cointelegraph 最近 24 小时 RSS 标题摘要，按币种与市场背景关键词筛选，最多 8 条，缓存 5 分钟。每条包含来源、链接、发布时间；AI 新闻引用必须对应本次提供的条目。
- 报告时效：5 分钟后、风险参数或持仓变化后隐藏旧仓位金额并提示重算；旧现货报告仅在历史中保留。
- Telegram：测试消息、报告手动/分析后推送、最新成交价预警、按北京时间每日一次自选简报。报告注明分析引擎、合约价格、保证金、新闻状态和引用。

## 使用顺序

1. 在「偏好与连接」调整**计划账户权益**、杠杆和风险参数。默认 10,000 USDT 与 3 倍杠杆仅为可编辑的计算假设，不是读取到的账户余额或交易所杠杆设置。
2. 添加自选币。核对币安 USDT 永续成交价、标记价和时间；行情缺失或过期时不提供新增仓位。
3. 选择「技术规则分析」或「AI 综合分析」，再生成单币报告或自选简报。默认方式和每日简报方式可在设置中保存。
4. 需要 AI 综合分析时，填写 API Base URL（通常以 `/v1` 结束）、模型 ID 和 API Key。没有模型不能发起 AI 分析，本地模型可不填 Key。无新闻或无新闻引用时明确标注仅作技术解读。
5. 配置 Telegram，保存并发送测试消息；验证成功后打开自动推送、每日简报。
6. 录入持仓，设置关键价位提醒，持续跟踪。

## 合约仓位测算

```text
风险预算 = 计划账户权益 × 单笔风险比例
止损幅度 = abs(观察入场价 - 计划止损价) / 观察入场价
已有初始保证金估算 = sum(持仓基础币数量 × 开仓均价 / 记录杠杆)
可用保证金假设 = max(0, 权益 - 权益预留 - 已有初始保证金估算)
名义仓位上限 = min(
    风险预算 / (止损幅度 + 预估往返成本率),
    单币剩余保证金额度 × 计划杠杆,
    可用保证金假设 × 计划杠杆
)
估算初始保证金 = 名义仓位 / 计划杠杆
估算止损损失 = 名义仓位 × (止损幅度 + 预估往返成本率)
```

多头止损在入场价下方，空头止损在上方。同币种已有反向持仓时暂停叠加反向新仓。保证金约束与止损预算同时生效；杠杆不提高风险预算。规则处于观望、行情异常或计划价位不适用时，新增仓位为 0。

当止损幅度加成本达到初始保证金比例的 80% 时，程序暂停新增仓位。该检查只是保守阈值，**不是币安强平模型或不会爆仓的保证**。没有读取账户、保证金档位、维持保证金、抵押品或全仓/逐仓状态，不提供精确强平价。持仓保证金为人工记录的估算值，不是交易所实际冻结金额。

当前费率下的单次资金费估算另外展示（正数为支出，负数为收入），不计入止损预算；实际费率可能变化、持有期间可能跨越多次结算。手续费、滑点、跳空和止损未成交均可导致实际损失超过预算。名义仓位尚未按交易所最小数量、步长或价格档位取整，不能直接用作下单参数。

报告是生成时的条件快照，有效期 5 分钟；即使尚未过期，也不表示触发条件已成立。每次开仓前重新生成并在币安核对。多个币种的报告各自使用同一权益假设，不能把金额简单相加作为组合下单预算。

## 新闻与 AI 的边界

规则信号只使用技术指标；新闻列表不参与规则信号与仓位公式。AI 模式可根据提供的新闻摘要评估事件如何支持或削弱技术观察，但不能修改程序计算的价位和仓位。模型只接收本次数据，不会自动联网补新闻。

新闻为英文媒体 RSS 标题与摘要，关键词相关性不等于已确认会影响该币种；不覆盖所有热点、交易所公告或宏观日历，未抓取文章全文、核实报道事实或验证事件因果。新闻源失败、近 24 小时没有匹配条目、演示模式均会明确展示。AI 无有效新闻引用时标注「AI 技术解读 · 热点未纳入」。模型输出仍可能出错，应核对原始来源。

币安合约接口为 `https://fapi.binance.com`，受服务器网络与地区限制影响。返回 HTTP 451 等错误时显示不可用，**不会回退现货、其他交易所或演示价格**。接口与字段说明见 [数据口径说明](docs/data-sources.md)。

## Telegram 配置

- 在 Telegram 通过 `@BotFather` 创建机器人，获取 Bot Token。
- 给机器人发送 `/start`。
- 通过 Telegram Bot API 的 `getUpdates` 查看会话的 `message.chat.id`，填写 Chat ID。群组 ID 可能为负数。
- 网页中点击「保存并发送测试消息」，确认送达。
- 「推送报告与到价预警」控制分析完成后的自动推送及到价提醒；历史报告的「推送」为明确的手动发送。
- 每日简报使用 `Asia/Shanghai` 时间，服务在当天设定时间之后启动也会补执行一次。
- 采用每天最多一次调度；网络失败后不自动重发整批，避免已送达消息重复。失败会记录，可手动重试。
- 演示模式暂停每日自动简报与真实价格预警；手动/分析后推送的演示报告有明确标签。

后台任务依赖服务运行。**浏览器可以关闭，但电脑休眠、断网或停止服务后，盯盘和推送会暂停。** 本地 Python 启动没有安装系统常驻服务；Docker Compose 配置了 `unless-stopped` 重启策略，仍需要 Docker 引擎持续运行。

## 配置与数据

网页设置保存在 `.data/ai2b.sqlite3`。密钥保存在 `.data/secrets.json`（文件权限 0600），API 仅返回是否已配置，不返回密钥内容。没有加密密钥存储；需要保护本机账户和磁盘。

也可以复制 `.env.example` 为 `.env`。服务只读取 `AI2B_` 开头的配置；已保存的网页连接配置优先于环境中的初始连接参数。环境密钥在本地未保存密钥时使用。`.env` 和 `.data/` 已加入 `.gitignore`。

Python 和 Docker 默认监听 `0.0.0.0`，应用接受域名和 IP 访问。反向代理需保留浏览器访问的原始 `Host`（含非默认端口）；写入接口接受相同 Host 的 HTTP / HTTPS 来源。无用户登录机制，任何能访问服务的人都能修改配置和触发推送；公网部署可在反向代理层配置访问认证。本地 Python 仅需本机访问时，可加 `--host 127.0.0.1`。

## 当前边界

- 只支持 Binance USDT 永续；没有币本位、交割合约或其他交易所回退。
- 每次完整分析使用同一数据快照；报价与各周期 K 线有独立时间戳。只使用已收盘 K 线；数据过期、近期 K 线有缺口时冻结新增投入建议。
- 盯盘是定时轮询，不是逐笔 WebSocket。浏览器 K 线每分钟刷新，报价按设置间隔更新。
- 没有交易账户同步、双向持仓、精确强平价、全仓账户风险模型、完整事件检索、回测绩效展示、自动交易或模型训练。
- 当前判断是可追溯的启发式分析，不是经验证的盈利模型；模型信心不等于实际胜率。
- 老项目的回测曲线及历史收益没有迁入，不沿用其中尚未修复的组合记账逻辑。
